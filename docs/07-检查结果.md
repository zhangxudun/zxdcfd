# 第 7 步测试需求：检查结果

> 对应 [工作流程](工作流程.md) 第 7 步。
> 产物：`结果.json`。通过条件：各项检查全部通过。
> 实现：未实现。测试：未实现。

## 1. 范围

- 测：四项基本检查（流量守恒、入口流量、监测值稳定、残差收敛）和两项一维对照（压差、出口烟温）的判定是否正确、阈值两侧是否判对、`结果.json` 里的数值是否算对、检查不通过时是否逐项给出结论、数据缺失时是否报错、是否不改动第 5、6 步的文件、重跑是否不留旧结果、命令行返回值是否能直接用于 CI。
- 不测：算例文件内容（第 5 步）、算例能不能跑完和日志有没有报错（第 6 步）、不通过以后回到哪一步（第 8 步）。
- 第 7 步只读 `算例信息.json`、`postProcessing/` 和 `log.simpleFoam`，只写 `结果.json`。不运行 OpenFOAM。读日志只为取残差，日志有没有报错仍是第 6 步的事。
- 结局分三种，测试要分清：
  - 全部通过：不报错，`结果.json` 里“通过”为真。
  - 检查不通过：数据齐全但有检查项没过。不报错，照样写 `结果.json`，“通过”为假，每一项都有结论。
  - 不能检查：缺文件、缺数据或数据不是有限数。报错，不写 `结果.json`。
- 测试点分两类：“造数”类由测试自己写 `算例信息.json`、监测数据和 `log.simpleFoam`，不需要 OpenFOAM，也不需要先跑第 1–6 步；“OF”类真的从第 2 步跑到第 6 步，再交给第 7 步。判定逻辑都放在“造数”类里测。

### 2.1 基准数据 D0（“造数”类）

测试在临时目录里写出下面的内容，当作一个已经跑完的算例。

`算例信息.json`：

| 键 | 值 |
|---|---|
| 密度 | 0.5 kg/m³ |
| 比热 | 1100 J/(kg·K) |
| 入口温度 | 600 K |
| 出口表压 | -200 Pa |
| 理论入口体积流量 | 10 m³/s |
| 多孔压降估算 | 150 Pa |
| 出口温度估算 | 580 K |
| 步数 | 100 |
| 监测量 | inletFlow、inletP、outletFlow、outletT |

监测数据 `postProcessing/<名字>/0/surfaceFieldValue.dat`，每个文件开头有两行 `#` 注释，后面 100 行数据，每行是“步号 值”，值全程不变：

| 监测量 | 值 | 含义 |
|---|---|---|
| inletP | -100 | 入口面平均压力，单位 m²/s²（压力除以密度） |
| inletFlow | -10 | 入口体积流量，m³/s。流入为负 |
| outletFlow | 10 | 出口体积流量，m³/s。流出为正 |
| outletT | 580 | 出口按流量加权的平均温度，K |

日志 `log.simpleFoam`，100 个时间步。每步先是一行 `Time = 步号`，后面依次是 Ux、Uy、Uz、p、p、T 的求解行，格式与 OpenFOAM 的日志相同（`求解器:  Solving for 名字, Initial residual = 值, Final residual = 值, No Iterations 次数`），最后一行是 `End`。初始残差全程不变：

| 方程 | 初始残差 |
|---|---|
| Ux、Uy、Uz、T | 1e-05 |
| p 第一次求解 | 1e-05 |
| p 第二次求解 | 0.5 |

- p 每步解两次，是仿照非正交修正。第二次的 0.5 不参与判断，D0 能通过就说明只取了第一次。
- 各测试点只写出与 D0 不同的地方。“倒数第 51 行”指从最后一行往前数 50 步的那一行，D0 里是第 50 行。“最后 51 行”指从倒数第 51 行到最后一行，D0 里是第 50 至 100 行。
- 监测数据的行和日志的时间步一一对应，“倒数第 51 步”和“倒数第 51 行”是同一步。行数改成别的值时，日志的步数跟着改。
- 改流量时入口和出口一起改，除非测试点专门测流量守恒。

### 2.4 判定约定

下面的“末值”指监测数据最后一行的值，“变化量”指最后 51 行里的最大值减最小值。“残差”指 `log.simpleFoam` 里每个时间步各方程第一次求解的初始残差（`Solving for 名字, Initial residual = 值`）；一步里同一个方程解几次的，只取第一次。

- 进出口压差 = inletP 末值 × 密度 − 出口表压。
- 入口流量 = −inletFlow 末值。出口流量 = outletFlow 末值。
- 吸热量 = 密度 × 入口流量 × 比热 ×（入口温度 − outletT 末值）。
- “流量守恒”：|inletFlow 末值 + outletFlow 末值| < 0.1% × |inletFlow 末值|。
- “入口流量”：|入口流量 − 理论入口体积流量| < 1% × 理论入口体积流量。
- “监测值稳定”要同时满足三条：数据多于 60 行；inletP 变化量 < 0.1% × |inletP 末值|；outletT 变化量 < 0.01 K。
- “监测值稳定”看的是最后 51 行整个窗口，不是只比首尾两行。首尾相等但中间振荡的数据判为不稳定；窗口之前的数据不参与判断。不足 51 行时算不出变化量，判为不通过。
- “残差收敛”：日志里出现过的每个方程，最后 51 步里残差的最大值都 < 1e-3。窗口之前的残差不参与判断。不足 51 步时取全部步数；步数够不够由“监测值稳定”管。
- “压差与一维解一致”：|进出口压差 − 多孔压降估算| < 3% × 多孔压降估算。
- “出口烟温与一维解一致”：|outletT 末值 − 出口温度估算| < 3% × |入口温度 − 出口温度估算|。3% 是相对温降说的，不是相对绝对温度。D0 里允许偏差是 0.6 K。
- 所有比较都是严格小于。测试只取阈值两侧的值，不取恰好等于阈值的值。
- 不对照一维时，“检查”里恰好四项，顺序是流量守恒、入口流量、监测值稳定、残差收敛。对照一维时再加压差、出口烟温两项，共六项。
- 每一项都要算，不能遇到第一项不通过就停。
- “说明”里要有判定用到的数值：流量守恒和入口流量写出两个流量；监测值稳定写出总步数和两个变化量；残差收敛写出日志的总步数和每个方程在窗口里的最大值；一维对照写出计算值和估算值，出口烟温还要写出允许偏差。
- “不能检查”的情况：算例目录或 `算例信息.json` 不存在；`算例信息.json` 读不了或缺少 2.1 表里用到的键；某个监测量没有数据文件、没有数据行、值不是有限数；四个监测量的行数不一样；没有 `log.simpleFoam`、读不了、里面没有残差，或某个残差不是有限数；要求对照一维但没有估算值。
- 运行一开始就删掉旧的 `结果.json`。所以报错以后目录里没有 `结果.json`。
- `结果.json` 是合法 JSON，里面没有 NaN 和 Infinity，中文键不转义，没有时间戳。
- 数值比较：由 D0 直接算出的值，相对误差 ≤ 1e-9。

## 5. 已定事项

下面几项工作流程里没有写明，现在定下来。实现时按这里做，要改先改本文。

| 事项 | 决定 | 依据 |
|---|---|---|
| 接口形式 | `check_result.py` 里的 `check_result(算例, 对照一维=False)`。算例是第 6 步的返回值或算例目录。能检查就返回字典，不能检查抛 `结果错误`。命令行是 `python check_result.py 算例目录 [--对照一维]`，全部通过返回 0，有检查不通过或不能检查返回 1，用法不对返回 2。测试放在 `tests/test_check_result.py` | 与 `run_case.py` 的写法一致；返回值的约定来自工作流程第 3 节 |
| 五项检查的算法和阈值 | 按 2.4 | 来源仓库 zhangxudun/cfd 的 `openfoam算例.py` 里的 `汇总结果`。除“监测值稳定”的算法见下一行外，原样移植。“残差收敛”是本仓库加的，见下面“残差要不要检查”一行 |
| “最后 50 步稳定”怎么算 | 看最后 51 行里的最大值减最小值，阈值不变；数据要多于 60 行 | 来源仓库只比较末值和 50 步之前的值，首尾相等但中间振荡时会误判为稳定，所以改成看整个窗口 |
| 残差要不要检查 | 检查，作为第四项基本检查“残差收敛”：最后 51 步里每个方程的初始残差最大值 < 1e-3 | “监测值稳定”只看两个监测量。端到端实跑里 S2 的 p 残差停在 2.9e-4 至 5.5e-4 之间，监测值看不出来。阈值取 1e-3，S1、S2 现在都能通过，只拦明显没收敛的算例；偏松，见第 6 节 |
| 出口烟温的 3% | 相对温降 \|入口温度 − 出口温度估算\|，不是相对绝对温度 | 同来源仓库。相对绝对温度的话 3% 是十几 K，起不到检查作用 |
| 进出口压差怎么取 | inletP 末值 × 密度 − 出口表压 | 同上。第 5 步把出口压力固定成 出口表压 / 密度 |
| 理论流量从哪里来 | 读 `算例信息.json` 的“理论入口体积流量” | `generate_case.py` 已经写了这一项，不必再乘一遍 |
| 检查不通过算不算报错 | 不算。照样写 `结果.json`，由“通过”和命令行返回值表示 | 第 8 步要看是哪一项没过，才能决定回到哪一步 |
| 结果里加“通过” | 加。来源仓库没有这一项，是在命令行里临时算的 | 第 8 步和 CI 读 `结果.json` 时不用再遍历“检查” |
| 没有一维估算又要求对照 | 报错，不当成检查不通过 | 来源仓库就是报错；工作流程第 4 节写的处理是“不做一维对照” |
| 默认对不对照一维 | 不对照 | 来源仓库的默认值 |
| 旧的 `结果.json` | 运行一开始就删 | 与第 6 步“先清旧结果”一致 |
| 第 7 步重不重复第 6 步的检查 | 只从 `log.simpleFoam` 里读残差，不重复判断日志有没有报错。但监测数据、残差缺失或不是有限数要自己拦住 | 第 7 步可以直接拿一个目录路径来跑，不能假定第 6 步刚跑过 |
| 测试怎么分 | 判定逻辑全用“造数”测，“OF”只测真实算例能通过 | 阈值两侧的数据靠真实求解凑不出来 |
