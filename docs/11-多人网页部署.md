# 多人网页部署

把网页版放到一台云服务器上，别人用浏览器打开网址、输入访问码就能用，不用装任何东西。计算在服务器后台排队进行，关掉网页不影响。

## 1. 准备服务器

| 项目 | 建议 |
|---|---|
| 配置 | 4 核 8 GB 内存起，硬盘 40 GB 以上。同时算 1 个任务约占 1 核、1–2 GB；S3 一组（含网格无关性）约 2–3 分钟 |
| 系统 | Ubuntu 22.04 / 24.04 |
| 网络 | 开放 8501 端口（只用 IP 访问时），或 80、443 端口（用域名 https 时） |
| 域名（可选） | 国内服务器用域名要先备案；域名解析到服务器公网 IP |

## 2. 安装和启动

```bash
# 装 Docker（官方脚本）
curl -fsSL https://get.docker.com | sudo sh

git clone https://github.com/zhangxudun/zxdcfd.git
cd zxdcfd
cp .env.example .env
nano .env                       # 改用户名和访问码，见第 3 节
sudo docker compose up -d --build
```

第一次构建要下载 OpenFOAM 镜像（约 1 GB）并安装 gmsh、Streamlit，需要几分钟。完成后浏览器打开 `http://服务器IP:8501`。

镜像里自带 OpenFOAM，计算直接在容器里跑（运行方式固定为“本机”），不需要在服务器上另装 OpenFOAM，也不需要把 docker 权限交给网页。

### 用域名和 https

在 `.env` 里填 `DOMAIN=cfd.你的域名.com`，然后：

```bash
sudo docker compose --profile https up -d --build
```

Caddy 会自动申请和续期 https 证书，用户打开 `https://cfd.你的域名.com`。这时可以在云服务器安全组里关掉 8501 端口，只留 80、443。

## 3. 用户和访问码

在 `.env` 里设置：

```
ZXDCFD_USERS=张三:k8Pq2xZr9vLm,李四:Tn4wY7cBs1Qe
ZXDCFD_ADMINS=张三
```

- 每人一个用户名和访问码，英文冒号分隔，多人英文逗号分隔。访问码请用随机长串，例如 `openssl rand -base64 12` 生成。
- 管理员能看到、取消、删除所有人的任务。
- 改完执行 `sudo docker compose up -d` 生效（不用重新构建），已有任务不受影响。
- 人多时可以改用文件：`ZXDCFD_USERS_FILE=/data/users.json`，内容是 `{"张三": "访问码", ...}`。
- 不设 `ZXDCFD_USERS` 就是单机模式，谁打开都能用，不要这样放到公网。

## 4. 限额和清理

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `ZXDCFD_WORKERS` | 1 | 同时计算几个任务，其余排队。4 核 8 GB 建议 1–2 |
| `ZXDCFD_MAX_JOBS_PER_USER` | 2 | 每人同时最多几个未结束（排队或计算中）的任务 |
| `ZXDCFD_MAX_CELLS` | 400000 | 网格单元上限，用户在界面上不能填得更大 |
| `ZXDCFD_MAX_TIME` | 7200 | 单次求解时限（秒）上限 |
| `ZXDCFD_KEEP_DAYS` | 7 | 任务结束后保留几天，到期自动删除；网页上传的临时文件 1 天后删除 |

上传文件限 50 MB（`.streamlit/config.toml`）。

## 5. 日常维护

```bash
sudo docker compose logs -f app                                 # 网页日志
sudo docker compose exec app tail -f /data/任务/worker.log      # 计算服务日志
sudo docker compose exec app ls /data/任务                      # 所有任务目录
git pull && sudo docker compose up -d --build                   # 升级
```

- 任务数据在 docker 卷 `zxdcfd-data` 里（容器内 `/data`），重建容器不会丢。备份：`sudo docker run --rm -v zxdcfd_zxdcfd-data:/d -v $PWD:/b ubuntu tar czf /b/zxdcfd-备份.tgz -C /d .`
- 升级或重启时正在算的任务会标成“出错：计算服务重启”，用户重新提交即可。尽量在没人计算时升级（管理员页面能看到全部任务状态）。

## 6. 已知限制

- 登录状态存在浏览器会话里，刷新网页要重新登录；任务存在服务器上，不受影响。地址栏里的任务号链接可以收藏。
- 访问码是管理员统一发放的，没有自助注册、改密码、找回密码。
- 网页进程里读 STEP、生成几何、三角化预览共用一把锁，多人同时操作时要排一下（一般不到 1 秒）；计算本身在独立进程里，互不影响。
- 一台服务器一个计算服务。要更多算力只能换更大的机器或调高 `ZXDCFD_WORKERS`，还不支持多台机器分担。
- 物理模型的限制与单机版相同，见 [用户使用说明](10-用户使用说明.md)“结果能信到什么程度”。

## 7. 验证

CI 的 docker 任务每次都会：构建镜像；在镜像里把 S1 经队列提交、由计算服务用镜像自带的 OpenFOAM 真算一次，要求任务完成且结论“通过”；再以多人模式启动网页，检查能访问。
